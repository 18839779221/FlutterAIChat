# Flutter UI Lab 微调

## 核心思想

先用一个小而独立的 Flutter 原生 Lab 入口作为调试空间，再把验证过的组件和动效迁移回正式页面。Lab 必须使用与 App 相同的 Flutter 渲染、主题 token、布局、手势和动画能力，这样 UI 反馈才基于真实可交付效果，而不是另一个技术栈里的幻觉。

这个 skill 的目的，是避免几个反复踩坑的模式：用口头描述讨论动效、用 HTML/CSS 做看似漂亮但无法复现到 Flutter 的 demo、只看静态截图就判断交互手感、或者在正式页面里边改边猜。

## 何时使用

用于这些场景：

- 首页、header、composer、按钮、chip、sheet、drawer、浮动工具栏等 UI/动效微调。
- 按压、hover、拖拽、打开/关闭、弹性、形变、模糊、毛玻璃、Liquid Glass 等交互效果。
- 用户正在判断“手感”“灵动”“质感”“塑料感”“凸起/内凹”等主观但必须落到真实画面的问题。
- 之前的 HTML/CSS demo、截图或口头描述已经和 Flutter 实际效果产生偏差。

不要把 Lab 当成最终生产验证。Lab 是快速调参空间；最终接入正式页面后，仍然需要生产路径验证和定向检查。

## 硬性约束

- 不要用独立 HTML/CSS 来调 Flutter UI 行为，除非用户明确要求 web-only 草图。
- 不要只靠文字描述判断动效质量；必须运行 Lab 并检查真实画面或截图。
- Web Lab 一旦约定了固定 origin，就保持同一个 host + port 持续迭代，避免频繁换端口导致验证链路和浏览器状态漂移。
- 不要把 Lab 接进 App 数据库或完整 provider 图，除非被调组件必须依赖真实状态。
- 不要让父级卡片拦截子按钮点击；Lab 里的每个交互组件必须能被直接按压、点击或拖拽。
- 不要只看 idle 静态态就说完成；至少检查静态、按压/展开中、释放/收起后的状态。
- 在把结果拿给用户前，先完成一轮自验证；只有在已验证、或遇到明确阻塞时，再和用户沟通当前结论。
- 用户明确否定过的方向要当成硬约束，例如“塑料感”“凸起小球”“内凹按钮”“外包气泡”“单侧扩张”。

## 已达成的设计原则

这些原则是当前 App 后续 UI 打磨的稳定方向。

- **真实实现优先于描述表演：** 用 Flutter 原生 Lab 判断 UI/动效，因为 hit testing、布局、blur、clip、gesture timing 和动画曲线都必须在真实可交付媒介里验证。
- **交互表面要回应用户触摸：** 按压时应该是被按对象本身发生可感知变化，而不是只让图标变暗，或把内容缩小到被手指遮住的位置。
- **被挤压时表面积应增加：** Liquid-like 控件的按压态应该像材料被轻轻压开，不能缩小、塌陷、内凹。
- **形变要符合用户心智：** 用户按在按钮/Chip 中心时，形状应从中心或感知锚点扩张；朝单侧变宽会被理解成布局位移，而不是材料响应。
- **Liquid Glass 先平整，再高光：** idle 状态应像一层薄而平整、略高于背景的玻璃层。避免凸起圆球、塑料鼓包、neumorphism 式外凸。
- **边缘承载材质感：** 浅背景上的玻璃需要可读边缘、平滑高光和轻微明暗对比；边缘应是一体的，不是一圈圈边框叠起来。
- **不要外包气泡：** 按压反馈属于同一个对象边界内部；如果在按钮外面出现独立膨胀 halo，会像套了一层气泡壳。
- **先删线，再加线：** 如果控件开始内凹、杂乱、机械，先删除层级和描边。优先保留一个清楚的表面模型，而不是叠内外边框、分割线、暗线。
- **动效要灵动但有因果：** 过渡应轻快、有弹性，并能解释用户动作导致了什么空间变化；不要为了“动”而做无来源的装饰动画。
- **Chrome 服务内容，不抢内容：** 首页顶部按钮、composer 控件、浮动栏应精致、鲜活，但仍然服从阅读/任务主表面。
- **Lab 使用产品语言：** 用户实际看到中文时，Lab 文案和控件标签也要中文化，否则字宽、节奏和用户评审都会失真。
- **交付前先自审：** 让用户看之前，先自己检查静态和交互态。如果动效无法完全截图，也要说明已验证什么、还需要用户确认什么。
- **验证循环要尽量短：** 能用热重载、浏览器刷新或局部重进页面完成验证时，不要默认整轮重启 `flutter run`。

## 工作流

1. **追踪真实组件路径**
   - 找到正式页面、Widget、theme token 和已有交互实现。
   - 明确要调哪些状态：idle、pressed、hover、focus、expanded、dismissed、loading 等。
   - 修改前先把当前问题说成具体视觉问题，例如边界不可见、像塑料、像内凹、图标不居中、按压无反馈。

2. **创建或复用独立 Lab 入口**
   - 入口优先命名为 `lib/main_<topic>_lab.dart`。
   - 页面优先命名为 `lib/pages/<topic>_lab_page.dart`。
   - 复用项目主题系统，例如 `AppTheme`、`AppThemeSpec`、`AppSpacing`、`AppRadius`、`AppMotion`、`AppTypography`。
   - Lab 保持确定性：固定样例文案、固定布局状态，必要时暴露调参滑杆。

3. **用 Flutter 构建可迁移组件**
   - 使用后续能迁移到正式页面的 Flutter Widget、Gesture、Animation 写法。
   - 复用真实 token 和字体；除非正在实验新 token，否则不要散落临时颜色、圆角、曲线。
   - 明确 clickable area 和 animated surface，避免父级命中测试吞掉子组件交互。
   - 如果要做居中按压扩张，用固定最大尺寸槽位包住居中的 animated child，不要让 `Row` 里的 child 直接变宽并推向一侧。

4. **按视觉契约调参**
   - 静态态：检查层级、边缘可读性、形状、图标/文字居中，以及表面是平整、凸起、内凹还是杂乱。
   - 按压态：检查同一个对象是否被挤压/扩张，而不是被外部气泡包住。
   - 释放态：检查回弹是否轻快、有因果，不要僵硬。
   - 多控件态：检查间距、分隔、相邻控件是否被异常推开。
   - 跨尺寸态：检查手机感宽度和 desktop/web 构图，不要把移动端布局拉满宽屏。

5. **运行并检查 Lab**
   - 使用仓库 Flutter 版本，优先 `fvm flutter`。
   - Web 迭代使用稳定 origin，并在同一轮任务里固定住它；如果该任务已有约定端口，继续复用原端口。
   - 推荐命令：
     `fvm flutter run -t lib/main_<topic>_lab.dart -d web-server --web-hostname 127.0.0.1 --web-port 7357`
   - 用浏览器截图或真机截图做视觉检查。动效要捕获或检查真实 pressed、dragged、opened 等状态，不只看 idle 截图。
   - 如果白屏，先看编译/运行日志和浏览器 console，不要猜。

6. **先在 Lab 内迭代**
   - 一次只改一个视觉假设：形状、边缘、填充、阴影、blur、动画曲线或布局。
   - 优先走短循环：代码改动后先尝试热重载；Web 场景优先页面刷新或复用已打开的 browser tab 验证。
   - 只有当热重载失效、入口变更、状态异常或编译器卡死时，才回退到重启 `flutter run`。
   - 每轮有意义改动后，运行格式化和定向分析：
     `fvm flutter analyze lib/main_<topic>_lab.dart lib/pages/<topic>_lab_page.dart`
   - 如果效果变差，先简化层级模型，不要继续加装饰。

7. **Lab 通过后再迁移**
   - 只有交互方向被接受后，才抽取可复用 Widget 或 token。
   - 迁移最小必要组件逻辑到正式页面，不要把 Lab 脚手架带进生产代码。
   - 如果同类组件后续还要继续调，保留 Lab 作为长期调试空间。

## Flutter Lab 设计规则

- 一个清楚的表面模型优先于多层边框；嵌套线条太多通常会显得内凹或杂乱。
- Glass/Liquid 效果需要亮部和暗部边缘信息，但边缘应该像一个整体，而不是多圈 outline。
- Liquid 按压扩张应从中心或感知锚点发生；单侧变宽会像布局 shift。
- 除非用户明确要求 neumorphism，否则避免凸起小球。平整玻璃需要的是克制边缘高光，不是隆起圆顶。
- 动效要解释因果：按压让对象被挤压扩张；sheet 从触发点或空间来源展开；drawer 应该像附着在边缘。
- 手势手感必须用真实 pointer event 调；idle 截图无法验证按压反馈。

## 验证清单

把 Lab 版本交给用户看之前，先确认：

- 已对改动 Dart 文件运行 `dart format`。
- Lab 入口和页面通过定向 `fvm flutter analyze`。
- Lab 能在 `http://127.0.0.1:7357` 或指定设备上运行。
- 已优先尝试热重载/刷新完成当前轮验证；如果没有，知道为什么必须重启。
- 已检查静态截图。
- 至少检查过一个相关交互态：pressed、dragged、opened 或 dismissed。
- 已逐条对照用户约束，例如不用 HTML demo、无塑料感、无内凹、无外包气泡、无单侧扩张、无父级拦截子按钮点击。

## 常见失败模式

- **HTML 漂移：** CSS demo 看起来不错，但 Flutter 复现不了。修正方式：立即移到 Flutter Lab。
- **反馈不可见：** 按压动画被手指挡住。修正方式：让边缘和表面响应，而不是只缩小内容。
- **单侧增长：** `Row` 子项朝邻居方向扩张。修正方式：固定最大尺寸槽位 + 居中 animated child。
- **外包气泡：** 按压反馈出现在按钮外层 halo。修正方式：把视觉响应收回同一对象边界内部。
- **内凹杂线：** 多层边框、内暗线让控件像 recessed button。修正方式：删除层级，回到单一表面模型。
- **只看静态：** idle 可接受但动效僵硬。修正方式：检查真实交互态后再判断。
