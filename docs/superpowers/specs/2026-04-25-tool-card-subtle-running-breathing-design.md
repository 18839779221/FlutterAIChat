# Tool Card 轻量 Running 呼吸动效设计

## 背景

当前工具卡片的 loading 态主要依赖状态文案与状态点，信息足够明确，但视觉上略静态。我们希望区分两类运行态表达：

- 重点卡片：用户需要一眼看出“这张卡正在工作”
- 低噪音卡片：保留轻量感，但不至于完全静止

## 目标

- 为重点卡片提供可感知但不过度的运行态反馈。
- 为低噪音卡片提供更克制的运行态反馈。
- 只在 `running` 态展示动效，避免完成态与失败态继续闪动。
- 保持当前卡片信息密度和布局不变，不引入新的交互。

## 非目标

- 不改造全局页面 loading。
- 不引入骨架屏、明显位移或缩放。
- 这次不处理超长路径在动画层的特殊排版问题。

## 方案

### 1. 覆盖范围

重点卡片：

- `web_search` workflow card
- `fetch_webpage` workflow card
- 通用 `ToolWorkflowCard` 中处于 `running` 的大卡片

低噪音卡片：

- `ToolInlineStepRow`
- `CompactToolRow`
- 其他同类 compact / inline tool row

### 2. 动效形式

重点卡片：

- 卡片表面增加一层很淡的斜向扫光
- 左侧状态点做轻微脉冲
- 状态胶囊保持静态

低噪音卡片：

- 不做整卡扫光
- 状态点做轻微脉冲
- 行背景保留极弱的明暗呼吸，作为辅助动态

### 3. 状态边界

- `running == true`：启用对应层级的动效
- 其他状态：维持静态展示

为了让 UI 层语义更清晰，卡片组件显式接收 `isRunning`，而不是在组件内部依赖文案或颜色推断。

### 4. 结构原则

- 不引入新的通用业务模型抽象
- 如需复用，仅抽离纯 UI 级别的动效组件
- 保持现有 renderer 与 mapper 结构，只补足 `running` 状态透传

## 风险与权衡

### 风险 1：动效太强，破坏当前卡片的低噪音风格

应对：

- 扫光透明度保持很低，不洗白正文
- 状态点脉冲幅度保持很小
- 背景呼吸 alpha 变化保持极小
- 不改变文案、尺寸和布局

### 风险 2：不同卡片的运行态反馈实现不一致

应对：

- 抽离共享的扫光、状态点、背景呼吸 UI 组件
- 统一由 `isRunning` 控制是否开启

## 验证

- Flutter analyze 需通过
- 重点卡片运行态可见淡扫光与状态点脉冲
- 低噪音卡片运行态可见状态点脉冲与极弱背景呼吸
- 完成态与失败态保持静态
- 行级卡片布局、文案、省略行为不回归
