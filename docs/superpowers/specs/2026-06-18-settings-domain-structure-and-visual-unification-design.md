# 设置域结构与视觉统一设计

## 1. 背景

当前应用的首页、设置页、模型管理页和 Provider 编辑页之间存在明显割裂：

- 首页已经形成一套稳定的产品气质，偏暖纸底、安静悬浮、阅读优先
- 设置域仍然停留在传统表单页和后台管理页语法
- 一级、二级、三级配置页面的职责边界不够清晰，导致后续新增配置时容易继续漂移
- 现有设置内容没有按“展示优先、变更其次、复杂编辑最后”的原则重排

这次重构的目标不是单纯换皮，而是同时完成两件事：

1. 重组配置内容，让设置页层级与操作路径符合当前项目的真实配置能力
2. 统一设置域与首页的视觉语言，但保留设置页作为工具域的效率感

## 2. 设计原则

### 2.1 内容优先于样式

- 先重排配置内容，再谈视觉统一
- 能在一级页展示的状态，不要提前下沉到二级页
- 二级页的核心职责是“变更配置”
- 三级页只在复杂对象编辑时出现

### 2.2 一级页展示优先

一级设置页应尽量承担“看全局”的职责，展示当前配置状态、摘要、数量、风险提示和当前默认值。

一级页不应退化成纯入口页，也不应把所有具体修改都塞进去。

### 2.3 二级页以变更为主

二级页用于实际修改配置，例如：

- 切换主题
- 修改默认运行时
- 增删 Provider 和模型
- 调整工具与 Skills 状态
- 修改兼容或实验项

二级页应承接一级页展示出的状态，并提供明确的变更动作。

### 2.4 三级页只处理复杂编辑

三级页仅在对象编辑较复杂时出现，例如：

- Provider 详情编辑
- 模型目录细节编辑
- API Style 选择
- Skills 安装表单

### 2.5 视觉统一但保留工具属性

- 统一首页同款底色、表面层级、字体节奏和按钮反馈
- 设置域比首页更密集，但不能变成传统灰白表单页
- 一级页更像摘要面板，二级页更像管理台，三级页更像专注编辑台
- 整个设置域应避免以外边框作为主要边界表达，不能继续维持明显的线框感

## 3. 设置域信息架构

### 3.1 一级页

一级页展示以下内容：

- 当前主题
- 当前默认 Provider / Model / Side Model / 生图模型
- 当前工具执行模式
- trusted / blocked 工具数量
- Skills 安装数量、启用数量和最近安装来源摘要
- 兼容适配器当前值

一级页的作用是让用户一眼知道“现在系统处于什么状态”，不是让用户在这里完成所有修改。

### 3.2 二级页

二级页承担配置变更，按功能域组织：

- 模型与运行时
- Agent 与工具
- 扩展能力
- 外观与兼容

二级页应提供列表、切换、启用/禁用、探测、测速、删除、编辑入口，但不把所有状态展示重复铺开。

### 3.3 三级页

三级页只处理复杂编辑：

- Provider 详情页
- 模型/能力编辑页
- API Style 选择 sheet
- Skills 安装 sheet

三级页不承担全局摘要职责。

## 4. 结合项目现状的内容重组

### 4.1 模型与运行时

应保留在一级页展示的内容：

- 当前默认 Provider
- 当前默认 Model
- 当前 Side Model
- 当前生图模型
- 当前接入状态

应放到二级页变更的内容：

- Provider 目录维护
- 模型列表维护
- 默认运行时调整
- 探测与测速
- 生图默认绑定

应放到三级页编辑的内容：

- Provider 名称、Base URL、API Key
- 模型列表细项
- API Style 选择

### 4.2 Agent 与工具

应保留在一级页展示的内容：

- 当前工具执行模式
- trusted 工具数量
- blocked 工具数量

应放到二级页变更的内容：

- 工具执行模式切换
- trusted 工具白名单维护
- blocked 工具黑名单维护

二级页不应只展示白名单，黑名单也应成为正式可见配置。

### 4.3 扩展能力

应保留在一级页展示的内容：

- 已安装 Skills 数量
- 已启用 / 已禁用数量
- 最近安装来源摘要
- 重复调用策略当前值

应放到二级页变更的内容：

- Skill 安装
- Skill 启用 / 禁用
- 重复调用策略切换

### 4.4 外观与兼容

应保留在一级页展示的内容：

- 当前主题
- 当前兼容适配器类型

应放到二级页变更的内容：

- 主题切换
- 兼容适配器切换

这类设置应明确标注为高阶或排障项，避免与主流程混淆。

## 5. 页面层级语义

### 5.1 一级设置页

一级页应表现为“设置首页”：

- 顶部给出整体配置概览
- 中部按配置域分组展示状态摘要
- 底部给出进入二级页的入口

一级页的核心体验是“看懂当前状态”，不是“开始填表”。

### 5.2 二级管理页

二级页应表现为“配置管理页”：

- 更高的信息密度
- 更明确的列表和操作
- 适合执行变更

二级页的核心体验是“改配置”，不是“读介绍”。

### 5.3 三级编辑页

三级页应表现为“专注编辑页”：

- 单对象编辑
- 单流程确认
- 减少横向干扰

三级页的核心体验是“把一件事改完”，不是“继续承载管理导航”。

## 6. 视觉统一规则

### 6.1 与首页共享的内容

设置域应共享首页的以下视觉语法：

- 暖纸底 / 安静悬浮面
- 低噪声边框与分隔
- 统一圆角和间距节奏
- 统一标题层级和字重
- 统一按钮反馈和按压态

### 6.2 设置域允许更工具化的地方

设置域可以比首页更工具化，但只允许在以下维度增强：

- 更高的信息密度
- 更明确的列表/表单分组
- 更直接的变更入口
- 更强的对象管理语气

不允许退回传统后台页语法：

- 灰白卡片堆叠
- 大量重复边框
- 表单区和说明区割裂
- 一级页只剩入口，不展示状态
- 用外边框硬切出每个区域的线框式组织

### 6.3 边界表达原则

设置域的边界不应再主要依赖外边框来表达，而应改用更现代的层次语言：

- 以表面明度差建立主边界
- 以留白和段落节奏建立组边界
- 以标题、状态摘要和内容密度建立信息边界
- 仅在必要时使用极轻的收边线，而不是用完整描边包裹整个模块

推荐的边界语言：

- `tone-on-tone` 面板：通过暖纸底与轻面板的明度差来分组
- `soft elevation`：通过极轻的浮感把当前关注块从背景中托起
- `content-led separation`：通过排版、留白和对齐来组织层次

不推荐的边界语言：

- 全模块明显描边
- 每行都带 divider
- 靠粗边框或高对比边框制造秩序
- 看起来像传统后台表格或设置清单的线框布局

## 7. 现有实现的主要问题

- `SettingsPage` 现在更像传统设置列表，而不是设置首页
- `ModelManagementPage` 和 `ProviderFormPage` 已经形成了局部风格，但没有统一层级语言
- `showAppBottomSheet` 是共享基础设施，但不同页面对其使用方式没有形成稳定规范
- `tool.blocked_names`、主题、适配器、Skills 摘要等内容目前没有被组织进统一的层级结构
- 当前多个设置模块仍然过度依赖外边框来表达边界，整体线框感偏重，不符合目标视觉方向

## 8. 预期落点

本次设计完成后，应达到以下结果：

1. 用户能在一级页快速看懂当前设置状态
2. 用户需要修改配置时，能明确进入二级页
3. 复杂对象编辑只在三级页发生
4. 设置域和首页共享同一套产品气质，但保留工具页的效率感
5. 后续新增配置时，有明确的归位规则，不再随意漂移
